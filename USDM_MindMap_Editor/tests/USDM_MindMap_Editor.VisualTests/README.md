# 下方インデント配置と接続線の実 UI 確認ホスト

本番の `Home` コンポーネント、CSS、JavaScript、Interactive Server、Core の接続線計算を再利用する確認専用ホストです。確認用の文書は Core テストと共有します。本番にシナリオ選択機能は追加しません。

プロジェクトルート `USDM_MindMap_Editor` から起動します。

```bash
dotnet run --project tests/USDM_MindMap_Editor.VisualTests/USDM_MindMap_Editor.VisualTests.csproj --urls http://127.0.0.1:5189
```

`http://127.0.0.1:5189/scenarios/single` をブラウザで開きます。末尾を次の名前に変更して各ケースを確認します。

- `single`: 単一の子
- `multiple`: 複数の子
- `deep-first-subtree`: 最初の子に深い子孫があり、そのサブツリー全体の下へ次の兄弟を配置
- `four-level`: 4 階層
- `multiple-backgrounds`: 複数背景
- `long-text`: 長文と折りたたまれた理由
- `long-expanded`: 理由を展開した状態

各画面で理由の展開・折りたたみ、ズーム、パン、ズームリセットを操作します。子の左辺が親の左辺から親幅の3/4だけ右へ寄り、最初の子が親の下辺から96px以上下へ配置されることを確認します。後続の兄弟と背景は、直前のサブツリーの全ノード・曲線を含む最下端から32px以上下へ配置します。接続線の始点・終点とノードの実矩形、曲線の張り出し、ノード内部の横切り、SVG の描画範囲も確認します。

このホストはソリューションへ追加していません。通常のアプリ起動と単体テストには影響しません。

## ブラウザ回帰確認

Playwright（Chromiumをインストール済み）が必要です。ホスト起動中に別のターミナルで、プロジェクトルートから実行します。通常のNodeモジュール解決でPlaywrightを読み込める場合、環境変数は省略できます。

```bash
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright node tests/js/connectors.browser.cjs
```

7ケースの実DOM境界から親幅3/4のインデント、親子の最小上下間隔96px、ID順の兄弟サブツリー間隔32px、複数背景の左端揃えと縦積みを検証します。サブツリーの最下端には親から入る曲線と内部の全曲線を含めます。ノード同士の非重複、曲線の全ノード非交差、下向き・右向きの制御点、SVG範囲、25%・200%ズーム、パン、リセット、長い理由の開閉3往復も検証します。

`artifacts/indented-layout/` にスクリーンショットと `results.json` を出力します。旧横方向配置の確認結果 `artifacts/connection-lines/` とは別に保存します。これらの生成物は既存の `.gitignore` により除外されます。

## 下辺の子追加領域・入力ダイアログの回帰確認

同じホストを起動した状態で、次を実行します。


25%表示で理由のsummaryと重なる楕円上側をクリックし、追加だけが起動することを確認します。MutationObserverで`details.open`の属性変化を監視し、理由が一時的に開閉してから戻される動作も不合格にします。追加のストレス試験ではオーバーレイの`pointer-events`だけを一時的に無効にし、実マウス入力がsummaryへ届く条件でも優先制御が働くことを確認します。同じ場所からのドラッグ・キャンセルで理由やパンへ切り替わらず、楕円外の四隅での理由クリックと、理由へフォーカスしたEnter / Spaceは有効であることを確認します。

`artifacts/elliptical-child-insertion/` に画面画像と `results.json` を保存し、旧4px帯の結果 `artifacts/child-insertion/` と配置試験結果は別に保持します。

## 追加領域の強調・終了後表示を Safari で手動確認する

この節は確認手順であり、実施結果や合格記録ではありません。今回の確認は利用者の指定に従って macOS の Safari を使用し、Chrome は使用しません。前述の Chromium 用回帰スクリプトの実行結果を、Safari の実操作結果として扱わないでください。

上記ホストを起動し、Safari で `http://127.0.0.1:5189/feedback` を開きます。4階層の文書と、本番の `Home` を使った操作画面に診断パネルを重ねたページです。画面・操作を初期状態へ戻す場合は再読み込みします。

`/feedback` と `feedbackDiagnostics.js` は確認専用ホストだけに存在し、本番アプリには搭載しません。診断はアプリの表示・入力状態を読み取り、パネルへ記録するだけで、強調用クラスの付け替え、フォーカス移動、疑似クリック、ノード追加などを行いません。パネル自体もポインター入力を遮りません。

### 診断記録の読み方

- `focus`: 対象の追加領域が実際の DOM フォーカス先か。
- `hover` / `fv`: ブラウザの `:hover` / `:focus-visible` が成立しているか。
- `inside`: 最後に観測したポインター位置が、現在のノード矩形から算出した楕円内か。新しい移動の発生を示す値ではありません。
- `class` / `fill` / `ring` / `title`: 実際のクラス、計算済み背景色、輪郭用の `box-shadow`、追加領域のツールチップです。`rootTitle` はキャンバス側のツールチップです。
- `dialog` / `visibility` / `active` / `zoom`: ダイアログ開閉、ページの可視性、ウインドウのアクティブ状態、アプリ内ズームです。
- 「直近の終了直後」: ダイアログが閉じた直後に採取した状態です。終了後にポインターを動かしてしまった場合も、この記録と現在値を区別します。
- 「入力イベント」: 直近の `pointerdown` / `pointerup` / `click` / `keydown` と、`detail`・キー・ポインター種別を表示します。入力起点の確認に使い、`click.detail` だけで入力方法を断定しません。

`hover=true` や `fv=true` だけでは、青い塗りつぶしが見えるとは限りません。実画面と `class`・`fill`・`ring` を合わせて確認します。ポインター起点の終了後は `focus=true` を保っていても、塗りつぶし・輪郭・ツールチップが残らないことが確認対象です。キーボード起点では塗りつぶしと区別した輪郭を確認します。

### ポインター起点の保存・キャンセル・Escape

背景、上位要求、下位要求の下辺中央をマウスまたはトラックパッドでクリックして開始します。クリック前の楕円内移動で強調・カーソル・ツールチップが表示され、送信中・ダイアログ表示中には解除されることを確認します。送信中の時間が短く実画面で観察できない場合は、その項目を未確認として記録し、下記の JavaScript 単体試験と区別します。

次の3つの終了方法を、それぞれ「ポインターが元の楕円内にある場合」と「楕円外にある場合」で確認します。

1. 必須本文を入力して保存する。
2. 入力してからキャンセルする。
3. 入力してから Escape で閉じる。

楕円内の条件では、開始後はポインターを動かさず、ダイアログ内の入力・Tab 移動・Enter / Space によるボタン操作で終了します。これらのキー操作をしても、開始時のポインター起点が変わらないことを確認します。楕円外の条件では、終了前にポインターを元の楕円外へ移動します。保存・キャンセルのボタンをポインターで押す場合も、終了時の位置は診断の `inside` で確認します。

終了直後はポインターを動かさず、起点へ DOM フォーカスが戻る一方で、青い塗りつぶし・輪郭・両方のツールチップが解除されていることを確認します。フォーカス復帰、ダイアログの消失、再配置に伴う領域への再進入だけで強調が戻らないことも確認します。その後、ポインターを実際に動かし、現在の楕円内でだけホバー表示が再開することを確認します。追加で親の位置が変化した場合は、元の画面座標ではなく最新の楕円を使用します。

### キーボード起点と操作の回帰確認

- Tab / Shift+Tab で追加領域へ移動し、塗りつぶしとは異なる輪郭が表示されることを確認します。対象へ移動できない場合は Safari・macOS のキーボードナビゲーション設定と操作を記録し、ポインターによる代用をキーボード確認済みと扱いません。
- Enter / Space のそれぞれで開始し、入力後に保存・キャンセル・Escape で終了します。起点フォーカスと輪郭が戻り、ホバーの塗りつぶしは残らないこと、続けて追加を繰り返せることを確認します。Tab / Shift+Tab で別の要素へ移ると、元の輪郭が消えることも確認します。
- アプリ内ズームを25%・100%・200%に変更して確認します。Safari自体のページズームとは区別します。楕円の縦10 CSS px・横がノード幅の半分という判定範囲と、境界・外接四隅・理由操作への優先順位が変わらないことを確認します。
- 楕円を強調した状態から、白い余白でのパン、ズーム、ズームリセット、理由の展開・折りたたみを行います。移動前の位置の強調が解除され、次のポインター移動では最新の矩形に従うことを確認します。楕円内の理由上では追加だけが起動し、楕円外の理由操作は通常どおり動作することも確認します。
- 楕円外へ移動する操作、追加領域からのドラッグの中止、別のアプリ・ウインドウ・タブへ切り替える操作で古い強調を解除します。復帰しただけではホバーが再開せず、新しいポインター移動で再開することを確認します。実機で発生させられない `pointercancel` / `lostpointercapture` は未確認として分け、単体試験の結果を実機操作と混同しません。

各条件について、Safari のバージョン、入力デバイス、ズーム値、開始方法、終了方法、ポインターの内外、終了直後の診断値、次の移動後の診断値を記録します。操作ツールの制約などで確認できない条件は、その理由を添えて未確認として残します。

## 背景単位の配置・移動・形式3の確認

今回の専用ページは `http://127.0.0.1:5189/positioning/{Scenario}/{ZoomPercent}` です。`ZoomPercent` は `25`、`100`、`200` を指定します。たとえば `/positioning/chain/100` を Safari で開きます。ページは確認用の入力文書を本番の `Home` へ渡すだけで、ポインターイベントの合成や、確認専用の追加・移動操作は実装していません。`Program.cs` の通常の確認ホストから利用できます。

| Scenario | 初期文書と確認目的 |
|---|---|
| `chain` | 4階層の背景001、その下へ近接する背景002・003、横に十分離れた背景004。理由展開・子追加で002→003が連鎖移動し、001と004を維持できるか確認 |
| `negative` | `chain` を平行移動し、001を `(-360.5, -220.25)` に配置。各倍率に合わせた保存済みパンで001を画面内へ表示し、負座標を正値へ書き換えずに描画・操作できるか確認 |
| `overlap` | 001・002・003の保存位置を意図的に重複させた文書。fixtureでは補正せず、`Home` の初期配置補正と利用者への通知を確認 |
| `legacy2` | `format_version: 2` のYAMLを実際にデシリアライズして渡す。選択倍率は元YAMLの `view.zoom` に含め、パン `(83.25, -31.5)` と要求001の理由展開を保ち、背景位置だけを補完するか確認 |

各ケースは再読み込みで入力文書からやり直します。再読み込み後の状態は保存ファイルの復元ではなくfixtureの再生成です。通常の「保存」「開く」ボタンは今回接続せず、YAML入出力の確認は以下のCore経路で行います。ファイルダウンロード・ファイル選択が動作したという確認結果にはしないでください。

### Coreでの読み込み・位置確定・保存

`UsdmYamlSerializer.Deserialize` は構造と値を検証しますが、背景位置を推測して追加したり、重複を補正したりしません。位置の補完・補正と通知情報の取得は `DocumentEditingSession` が担当します。形式1・2と、位置が不足する形式3もこの経路で読み込みます。

```csharp
using USDM_MindMap_Editor.Core.Editing;
using USDM_MindMap_Editor.Core.Serialization;

// inputYaml は読み込み対象のYAML文字列。
var serializer = new UsdmYamlSerializer();
var loaded = serializer.Deserialize(inputYaml);
var session = new DocumentEditingSession(loaded);

// UI側は初期位置補完と、既存位置の重複補正を区別して通知する。
var initializedIds = session.InitializedBackgroundIds;
var correctedIds = session.AutomaticallyMovedBackgroundIds;

// 全背景の確定位置を含む形式3を生成する。DOM実測値やドラッグ候補は含めない。
string outputYaml = session.Serialize(serializer);
```

Serializerへ直接、背景位置が不足する文書を渡して保存すると「保存前に背景の配置位置を確定してください」という検証エラーになります。Serializer内で初期配置を行うことはありません。保存文字列の生成は入力文書を書き換えず、実際の保存処理が成功する前に `MarkSaved()` を呼ばないでください。

Core試験はプロジェクトルートから実行します。

```bash
dotnet test tests/USDM_MindMap_Editor.Core.Tests/USDM_MindMap_Editor.Core.Tests.csproj
```

### Safariでの操作手順

この確認も macOS の Safari を使用します。利用者指定に従いChromeは使用せず、過去のChromium試験結果を今回の合格結果へ流用しません。以下は手順であり、合格記録ではありません。

1. 各ケースを25%・100%・200%で開き、初期描画とDOMサイズ補正が落ち着いた後の背景位置・状態表示を記録します。SVGの接続線、長文、負座標側の描画に欠けがないか確認します。アプリ内倍率とSafari自体のページズームは区別します。
2. `chain` の要求001で理由を展開し、001を固定したまま002・003が必要な範囲だけ下がり、横に離れた004は動かないことを確認します。理由を閉じても他背景を詰め直さないことを確認します。初期化し直し、下位要求001-001の下辺から仕様を追加する操作でも同様に確認します。
3. 背景本体を空いた場所へドラッグし、背景・全子孫・接続線が同量移動すること、確定時だけ位置と変更状態が更新されることを確認します。別ツリーへ重なる位置で離すと開始位置へ戻り、他背景は動かず、拒否の通知が出ることを確認します。途中の最後の空き位置へ吸着する動作とは区別します。
4. ドラッグをEscapeで取り消し、別ウインドウ・別アプリへの切り替えでも取り消されることを確認します。実質移動なし・取消・無効移動では、新たな位置確定や未保存変更を作らないことを確認します。ドラッグ中のズーム・パンや子追加が混在しないことも確認します。
5. 空白をダブルクリックして背景入力を開き、保存したときだけクリック位置を基準に背景が追加されることを確認します。取消・空白本文エラー、ノード・子追加楕円・接続線・操作部品上のダブルクリック、パン操作では誤追加されないことを確認します。ツールバーの背景追加と、既存の子追加・理由操作も確認します。
6. `negative` でパンを往復し、ズームを変えても接続線とノードがずれず、ドラッグ確定位置が画面座標ではなくキャンバス座標で扱われることを確認します。`overlap` では初期補正の通知、`legacy2` では保存済み倍率・パン・理由展開と位置補完を確認します。

読取専用でDOMを確認できる場合、背景別 `.tree-nodes` の `data-position-x` / `data-position-y` は確定済みのグローバルキャンバス座標です。ドラッグ中の見た目の `transform` を保存位置と混同しないでください。`.mindmap-canvas` の `data-layout-revision` と `data-unsaved` も変更前後を記録できます。ただし、DOMサイズ補正でもリビジョンは変わり得るため、初期値が常に1であると仮定せず、操作前の安定した値と比較します。

実機で `pointercancel` やキャプチャ喪失を発生させられない場合、または操作ツールでドラッグ・ダブルクリック・状態読取りができない場合は、未確認の条件と理由を記録します。単体試験、ルートのHTTP応答、画面が開いたことだけを実ジェスチャー確認の代わりにしません。過去の `artifacts/connection-lines/`、`indented-layout/`、`child-insertion/`、`elliptical-child-insertion/` や強調残留対策の記録は今回の背景位置機能の結果として再利用せず、今回のケース名・倍率・操作・環境を明記した別の記録を作成します。
