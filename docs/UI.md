# USDM_MindMap_Editor UI 設計書

作成日: 2026-07-15

## 1. 目的

本書は、USDM_MindMap_Editor の画面構成、操作、ノード表示、ダイアログ、状態表示を定義する。

## 2. 基本方針

- マインドマップ感覚で要求と仕様を編集できること
- ノード追加操作を少なくし、入力に集中できること
- ID はユーザーが手入力せず、自動採番すること
- YAML への保存結果が Git 管理しやすいこと
- ノード間の関係が一目で分かること

## 3. 画面構成

```text
┌──────────────────────────────────────────────┐
│ ツールバー                                    │
├──────────────────────────────────────────────┤
│                                              │
│                 キャンバス                    │
│                                              │
│  背景 / 上位要求 / 下位要求 / 仕様ノード       │
│                                              │
├──────────────────────────────────────────────┤
│ ステータスバー                                │
└──────────────────────────────────────────────┘
```

上図は上部メニューの表示状態を示す。本書の「上部メニュー」は既存のツールバーを指し、OS・ブラウザのメニューとは区別する。非表示時はツールバーを折り畳んでキャンバスを広げ、左上の切替ボタンだけを残す。ステータスバーは折り畳み対象に含めない。

## 4. ツールバー

表示する操作は、左から次の5件の順とする（2026-10-28変更）。折り返し表示とTab移動でも同じ順序を維持する。左上の円形のメニュー表示切替ボタンは別枠であり、この順序には含めない。

円形の表示切替ボタンと「新規」の間にあるアプリタイトル「USDM MindMap Editor」は上部メニューから削除する。機能ボタン群は円形ボタンの右隣から左詰めで配置し、タイトル用の表示枠・固定幅・空白を残さない。円形ボタンの操作領域とフォーカス輪郭に重ならない必要な余白だけを確保する。

狭い画面では機能ボタン群の使用可能幅に応じて折り返し、後続行も機能領域の左端へ揃える。タイトルを削除した分の空白や独立した空行を残さない。円形ボタンの位置・寸法・折り畳み動作と、5ボタンの順序は変更しない。

削除対象は画面内の上部メニューのタイトル表示だけとする。ブラウザのタブタイトル（`PageTitle`）、文書タイトル、プロジェクト名 `USDM_MindMap_Editor` は変更しない。メニュー領域のIDと表示切替ボタンのアクセシビリティ上の対応付けも維持する。

| 操作 | 内容 |
|---|---|
| 新規 | 空の USDM 文書を作成する |
| 開く | YAML ファイルを読み込む |
| 保存 | YAML ファイルをブラウザのダウンロードとして保存する |
| エクスポート | メニューから USDM 表へ変換してダウンロードする |
| 背景追加 | 背景項目を追加する |

上部メニューの「検索」「ズームリセット」ボタンを削除する。これはボタン配置の変更であり、§11の検索対象・検索結果仕様や、100%表示・パン初期化の処理自体を削除する変更ではない。代替の起動ボタン・メニュー・ショートカットは今回追加・確定しない。

2026-10-28に、`Home.razor` の操作群を上記5ボタンへ変更した。各ボタンに `tabindex="0"` を明示し、SafariのTab移動と狭幅の折り返しでもDOM順を維持する。検索・ズームリセットはボタン要素を除去し、既存リセット処理は保持した。新規・開く・保存・エクスポートには押下処理が接続されていない。背景追加は接続済みで、形式3の読込・補完・保存はCoreまで実装されている。入力ダイアログ内の「保存」は実行中の文書への確定であり、ツールバーのファイル保存とは区別する。今回の確認結果・未確認範囲は [QA_Q_sheet.md](QA_Q_sheet.md) D-14に記録する。

2026-10-28にタイトル削除・左詰めを実装した。`Home.razor` のツールバー内の `strong` と、CSSのタイトル用の間隔・狭幅の縦並び指定を除去した。機能領域は使用可能幅を使って左詰め・折り返しを行う。左余白は既存の切替ボタン直径36pxと余白8pxから52pxを確保し、切替ボタンの右端44px・フォーカス輪郭の外端48pxと重ならないようにした。`PageTitle` とメニュー領域のID・`aria-controls` は保持する。今回の試験結果・未確認範囲は [QA_Q_sheet.md](QA_Q_sheet.md) D-14に分けて記録し、既存の5ボタン化の試験結果を流用しない。

ノード構造が変わった場合と YAML 読み込み後は、背景配置位置を基準にツリー内部を自動整列する。背景のドラッグによるツリー全体移動を提供し、個別ノードの位置調整は提供しない。

Fit All と Fit Selection は将来対応とする。ズームリセットボタンを削除しても、既存のリセット処理は後続の起動導線から再利用できるよう保持する。

### 4.1 上部メニューの折り畳み（2026-10-28実装）

編集画面の左上隅に円形の切替ボタンを常時表示する。キャンバス内のノードではなく画面上の固定操作とし、表示・非表示の切替、パン、ズームによってボタンの位置や大きさを変えない。表示中はツールバーの文字・操作群と重ならない場所を確保し、非表示中もボタン自体を隠さない。

| 上部メニューの状態 | ボタン内のアイコン | ツールチップ・読み上げ名 | 押下結果 |
|---|---|---|---|
| 表示中 | 上向きの山形（ChevronUp） | メニューを隠す | ツールバーを上へ折り畳む |
| 非表示中 | 下向きの山形（ChevronDown） | メニューを表示 | ツールバーを下へ展開する |

- アイコンは次に実行する操作の方向を表す。文字の `V` や `>` を代用せず、同じ図柄・線幅の上下の山形アイコンを使用する。
- 切替ボタン以外のツールバー領域を折り畳み、キャンバスへ高さを戻す。透明にするだけで元の高さを残す動作にはしない。ボタンが残るだけのためにツールバー全高を確保しない。
- マウス主ボタンまたはトラックパッドの通常クリックで切り替える。ホバー離脱・キャンバスクリックだけで自動的に閉じたり、開いたりしない。
- `Tab` / `Shift+Tab` でボタンへ移動でき、`Enter` / `Space` で切り替える。キーボードフォーカスは視認可能な輪郭で示す。
- ボタンは標準のボタンとして扱い、`aria-expanded` は表示中 `true`、非表示中 `false` とし、`aria-controls` で対象のツールバー領域と対応付ける。アイコンだけに意味を依存させない。
- 非表示のツールバー操作へTab移動・クリックできないようにし、支援技術からも非表示とする。隠れる操作部品へフォーカスを残さず、切替後も切替ボタンへフォーカスを維持または復帰する。
- 切替ボタン上の操作を背景追加のダブルクリック、パン、ツリー移動、子追加として扱わない。ダイアログ表示中・追加確定処理中・パンまたはツリーのドラッグ中は、既存の競合制御に合わせて切替を受け付けない。
- 切替だけではツリーの再配置、背景位置変更、ズームリセットを行わず、現在のズーム倍率・パン値・選択状態を維持する。通常の再描画でも表示状態を勝手に戻さない。
- 表示状態を復元しない初期動作は既存どおり表示中とする。ブラウザ再読込・次回起動へ引き継ぐかは未決定とし、未決定の間は実行中のWeb UI状態だけで管理する。YAMLや文書の未保存変更・Undo / Redoへ追加しない。

円の直径、アイコン寸法、左上の余白は `WebUiSettings` で管理し、暫定UI評価値としてそれぞれ36px・20px・8pxを採用した。正式値の決定と折り畳み状態の永続化は [issues.md](issues.md) の未決定事項として維持する。座標系への影響は [LayoutDesign.md](LayoutDesign.md) §9.6、試験観点は [QA_Q_sheet.md](QA_Q_sheet.md) D-14を参照する。

実装では `Home.razor` の実行時状態で表示を切り替え、同じSVGパスを180度回転して上下の山形を示す。標準ボタンに `tabindex="0"` とフォーカス輪郭を設け、ツールバーの `hidden` と明示的な `display: none` で非表示項目を操作対象から除外する。キャンバスDOMは維持し、切替完了後にボタンへフォーカスを復帰する。今回の自動試験とSafariでの一部確認・未確認範囲は上記QA資料に記録し、過去の操作試験結果とは区別する。

### 4.2 ファイル操作ボタンの設計粒度点検（2026-10-28）

4ボタンとも、正常系の着手に使える要求はあるが、UIを含む一連の処理を独自判断なしで完成させる仕様は揃っていない。以下は不足の整理であり、未決定事項を今回確定するものではない。

| ボタン | 定義済み・利用可能な内容 | 完成前に必要な判断 | 判定 |
|---|---|---|---|
| 新規 | 空のUSDM文書を作成する。空の文書モデルとセッション生成処理は利用可能 | 未保存確認、タイトル・保存名、ビュー・選択・キャッシュ等の初期化範囲、履歴と未保存判定の扱い | 一部不足 |
| 開く | YAMLの親子関係・ビューを復元する。Coreは形式1・2・3の読取・検証・背景位置補完に対応 | 未保存確認、ファイル選択取消、許容拡張子・容量・文字コード、読込失敗時の元文書維持とエラー表示、未知キー等の互換性方針 | 一部不足。Coreは先行実装済み |
| 保存 | `.yml`をブラウザダウンロードとして保存する。Coreは固定順・形式3の出力に対応し、理由未入力では警告しない | 既定ファイル名・読込名の再利用、保存対象スナップショットと直前ビュー同期、保存済み判定の時点、失敗時・保存中編集の扱い | 一部不足。Coreは先行実装済み |
| エクスポート | USDM表をダウンロードする。理由空欄は警告し、確認後に続行可能 | `.xlsx` / `.csv`等の形式、列・シート・行の単位、仕様なし要求・関連要求の出力、警告UIと取消・出力名・失敗表示 | 不足。出力仕様の決定が先行 |

実装根拠は `Home.razor`、`DocumentEditingSession`、`UsdmYamlSerializer` である。`Serialize()` と `MarkSaved()` は存在するが、ブラウザダウンロードの実行や成功判定を実装済みとは扱わない。現在の初期画面はサンプル文書を表示しており、新規ボタンが空文書へ切り替える処理は未実装である。

未保存確認はIssue #027、履歴範囲は#026、互換性は#024、表出力は#025を参照する。ファイル選択・保存名等の追加確認は [QA_Q_sheet.md](QA_Q_sheet.md) D-02・D-05・D-11へ整理する。優先すべき判断は、新規・開くの文書破棄防止、保存名・保存済み判定、エクスポート形式と行・列構成である。

## 5. キャンバス

キャンバスは以下を満たす。

- 無限スクロール相当の広い作業領域
- ドラッグによるパン
- 空白のダブルクリックによる背景追加
- 背景本体のドラッグによるツリー全体移動
- ホイールまたは UI 操作による25%から200%のズーム
- 1操作あたり10%を基本単位とするズーム
- 自動整列・自動配置されたノードの表示
- 接続線の表示
- ノード選択状態の表示

新規文書の初期表示は100%とする。ホイールでズームする場合はポインター位置を中心とし、ポインターが指していたキャンバス上の位置がズーム前後で可能な限り同じ画面位置に残るように表示する。保存済み文書を開く場合は、保存されたズーム倍率とパン位置を復元する。配置と座標変換の詳細は [LayoutDesign.md](LayoutDesign.md) を参照する。

## 6. ノード種別

### 背景ノード

表示項目:

- ID
- 背景本文

背景ノードはサブツリーの最上部に表示する。上位要求は背景ノードの下へ右にインデントして表示し、背景ノードの下辺周辺の追加領域から作成する。背景は保存位置を復元し、本体のドラッグでツリー全体を移動できる。位置未保存の背景は、ツリー同士が重ならない既定の空き位置へ配置する。

### 上位要求ノード

表示項目:

- ID
- 要求
- 理由

操作:

- 下位要求追加
- 編集
- 削除
- 理由の展開・折りたたみ

### 下位要求ノード

表示項目:

- ID
- 要求
- 理由

操作:

- 仕様追加
- 編集
- 削除
- 理由の展開・折りたたみ

### 仕様ノード

表示項目:

- ID
- 仕様
- 関連する下位要求数

操作:

- 編集
- 削除
- 関連する下位要求の設定

仕様の関連する下位要求は、所属先とは別の参照としてノード内に件数を表示する。親子接続線は所属先の下位要求との間だけに表示する。

### 配色

初期版の配色は以下とする。

| 対象 | 配色 |
|---|---|
| 背景ノード | 青 |
| 要求ノード | 緑 |
| 仕様ノード | 黄 |
| ノードの文字と枠線 | 黒 |
| キャンバス | 白 |

配色のユーザー設定は将来対応とする。

## 7. ノード配置

初期表示での配置方向:

- 親ノードを上に、子ノードをその下へ右にインデントして配置する
- 子ノードの左辺を、親ノードの水平方向の中心と右端の中間位置へ揃える
- 同じ親を持つ子ノードは左辺を揃え、上から下へ並べる
- 次の兄弟ノードは、先の兄弟の子孫・接続線を含むサブツリー全体の下へ配置する
- 同じ親を持つ兄弟ノードはID昇順で表示する。背景のID順は位置未保存時の初期配置順とし、保存・移動した背景を並べ直さない
- 放射型や従来の横方向の階層別配置への切り替えは初期版では提供しない
- ノード内容や表示状態が変わっても、ノード同士が重ならないことを優先する

兄弟サブツリー間の上下余白と背景自動配置の余白は32px、親の下辺と最初の子の上辺の上下余白は96px、初期配置のキャンバス外周は96pxを初期値とする。背景の重複解消では右・下の移動方向へ32pxの余白を確保する。手動で移動した背景を外周やID順へ強制的に戻さない。水平位置は親の幅に合わせて決め、親子を上下に離して重複を避ける。必要な場合は上下間隔を広げる。正式な共通幅が280pxなら、子の左辺は親の左辺から210px右の位置となる。

v1.0 では背景、上位要求、下位要求、仕様を共通の固定幅で表示する。可変幅と種類別固定幅は採用しない。正式な初期幅は `240px`、`280px`、`320px` の UI 比較後に確定し、`280px` を暫定実装値かつ第一候補とする。

幅の比較では、短い要求、2〜3行の通常要求、長い要求と理由、英数字を含む要求、4階層表示時のキャンバス占有量、ノード高さ、可読性、画面内情報量を確認する。正式決定前は `280px` を確定値として扱わない。

すべてのノードは最低 `110px` の高さを確保する。操作ボタンや接続操作などの領域は、初期値として高さ `32px` を確保し、UI 確認後に調整できるものとする。

手動並べ替えは v1.0 では提供しない。将来手動順を保存する場合は手動順を優先し、同順位は ID 昇順、手動順がないノードも ID 昇順で安定して表示する。詳細な配置規則は [LayoutDesign.md](LayoutDesign.md) を参照する。

階層と表示方向（各階層で下へ進み、右へインデントする）:

```text
背景
    上位要求
        下位要求
            仕様
```

## 8. ノード追加操作

### 空白からの背景追加

キャンバス空白を主ボタンでダブルクリックすると、背景入力ダイアログを開く。保存時に、ダブルクリックした位置を背景の左上として追加する。入力エラーでは確定せず、キャンセルでは追加しない。背景が重なる場合は自動配置で重複を解消する。ノード、子追加楕円、接続線、操作部品、ダイアログ上は対象外とし、パン後のクリックでも誤追加しない。

ツールバーの「背景追加」も維持し、この場合は既存ツリーの下の空き位置へ配置する。ダイアログ表示中の連打で重複起動しない。座標の扱いは [LayoutDesign.md](LayoutDesign.md) §9.5を参照する。

### 下辺周辺の追加領域

子ノードの追加は、親ノードの下辺中央を中心とする楕円形の操作領域から行う。ノード内に独立した追加ボタンや＋ボタンは表示しない。

| 親ノード | 下辺周辺から追加する子 |
|---|---|
| 背景 | 上位要求 |
| 上位要求 | 下位要求 |
| 下位要求 | 仕様 |
| 仕様 | 追加対象なし。追加領域を設けない |

- 楕円の中心は下辺の中点とする。縦の全長は画面上10 CSS pxで、ノードの内側5px・外側5pxに広がる。
- 横の範囲はノード左端から下辺長の1/4の位置から3/4の位置までとする。楕円の横幅はノード幅の1/2となる。
- ズーム25〜200%でも縦の全長を画面上10 CSS pxに保ち、横幅は表示中のノード幅へ追従させる。
- 判定は楕円の内側と境界のみとする。外接する長方形の四隅や、下辺の左右1/4の区間は追加対象にしない。
- 有効なホバー中は楕円領域を強調し、ポインターカーソルと「上位要求を追加」「下位要求を追加」「仕様を追加」のツールチップを表示する。強調によってノード寸法や配置を変えない。追加後のフォーカス復帰だけを理由にホバー強調を表示しない。
- マウス主ボタンの単一クリック、またはトラックパッドの通常クリックで、そのノードを親とする入力ダイアログを開く。右クリックでは追加しない。あらかじめ親を選択しておく操作は不要とする。
- ダイアログの保存で入力を検証し、IDを採番して子を追加する。キャンセルや入力エラーだけでは文書へノードを追加しない。
- 接続線の起点と楕円領域が重なっても、楕円内のクリックを受け付ける。楕円外の接続線クリックでは追加しない。
- 楕円内で理由の展開・折りたたみ領域と重なる場合は、子追加を優先する。理由の文字やV部分の上であっても、楕円内なら子追加ダイアログだけを開き、理由の状態は変えない。
- 楕円外の理由操作は通常どおり行う。楕円外の本文・編集・削除操作では子追加を起動しない。追加領域からのドラッグをパンや追加として扱わず、ドラッグがキャンセルされた場合も理由操作へ切り替えない。
- ダイアログが開いている間の連打で、ダイアログやノードを重複生成しない。
- 領域はキーボードフォーカス可能とし、キーボード操作で到達した場合は塗りつぶしと区別した楕円の輪郭でフォーカスを示す。`Enter`または`Space`で同じ追加操作を実行できるようにする。読み上げ名はツールチップと同じ操作名を使用する。キーボードではフォーカス中の操作対象を使用し、理由操作にフォーカスした場合は理由の展開・折りたたみを行う。

背景自体の追加は空白のダブルクリックまたはツールバーの「背景追加」から行う。子追加楕円は背景ドラッグより優先し、楕円から始まる操作をツリー移動へ切り替えない。子追加領域の画面座標による判定と操作競合の詳細は [LayoutDesign.md](LayoutDesign.md) §9.3・9.4を参照する。

2026-10-27実装状況：3種の子追加、背景追加、入力ダイアログ、必須入力・親階層・関連下位要求の検証に加え、縦10px・横がノード幅の半分の楕円判定と、理由操作に対する子追加の優先制御も実装・検証済みである。楕円外接長方形の四隅では下層の理由操作を妨げず、楕円内のクリックでは理由の状態変化自体を発生させない。理由は任意、仕様の関連先は所属先を除く下位要求から複数選択する。既存ダイアログのモーダル、保存・取消、終了時のフォーカス復帰は維持する。楕円領域も通常表示には文字・＋記号を置かず、ホバー・フォーカス時だけ強調する。旧仕様と楕円仕様を区別した試験履歴は [QA_Q_sheet.md](QA_Q_sheet.md) D-14を参照する。

### 追加領域の強調と終了後の表示

子追加の楕円は操作箇所を示す一時的な表示とし、追加完了・親ノード選択を示す恒久的な青い印にはしない。2026-10-27の追加後に青い楕円が残る利用者報告を受け、表示規則を次のとおりとする。

| 状態 | 表示・動作 |
|---|---|
| 通常・ポインターが楕円外 | 透明。追加可能な範囲とキーボード操作は維持する |
| ダイアログがなく、最新のポインター操作が現在の楕円内 | ホバー強調・ツールチップを表示する |
| 追加要求の送信中・ダイアログ表示中 | 元の楕円のホバー強調・ツールチップを解除する |
| マウス・トラックパッド起点のダイアログを保存・キャンセル・Escapeで終了 | フォーカスは起点へ戻すが、青い塗りつぶしを解除し通常表示へ戻す |
| キーボード起点のダイアログを終了 | 起点へフォーカスを戻し、操作を継続できる輪郭表示を維持する。ホバーの塗りつぶしは残さない |

- 追加操作を開始した入力方法を記録する。ダイアログ内で文字入力したことやEnterで保存したことだけでは、マウス起点をキーボード起点へ変更しない。
- マウス起点の終了直後は、ポインターが元の位置にあっても自動的にホバー表示を復活させない。次のポインター移動・再進入で最新の楕円内にあることを確認してから再表示する。
- 保存・キャンセル・Escape・ポインターキャンセル・領域外への移動・画面非アクティブ化で古いホバー表示を解除する。パン・ズーム・再配置後も、移動前の座標による強調を残さない。
- フォーカスを失わせるだけの対処や、すべてのフォーカス表示を無効化する対処は行わない。Tab / Shift+Tabで楕円へ移動した場合とキーボードで追加を繰り返す場合は、操作位置を確認できること。
- 強調の解除によって楕円の形状・10pxの縦寸法・ヒット判定・理由操作に対する優先順位を変更しない。

2026-10-27に残留対策を実装した。塗りつぶしは最新のポインター移動で検証したホバーだけに限定し、ネイティブの`:hover`・`:focus-visible`とは切り離した。起点の入力方法を要求開始時に固定し、キーボード用の輪郭は画面上2 CSS pxの内側線として表示する。DOMフォーカスの復帰は維持する。JavaScriptの状態遷移試験とSafariでの確認範囲・残項目は [QA_Q_sheet.md](QA_Q_sheet.md) D-14、実装の詳細は [LayoutDesign.md](LayoutDesign.md) §9.4・17.1を参照する。実UIの全受け入れ条件を合格としたものではない。

## 10. ノード削除

親ノードを削除する場合は、配下の子要素をすべて削除する。削除確認ダイアログには削除対象のノード数を表示する。

確認ダイアログには「今後この確認を表示しない」チェックボックスを置く。選択結果はブラウザに保存し、以降の削除では確認ダイアログを表示しない。設定は将来の設定画面から再有効化できるようにする。

## 11. ノード検索

2026-10-28のメニュー変更で上部の検索ボタンは削除する。以下の検索仕様は保持するが、起動導線は未決定とし、別の検索ボタンやショートカットを暗黙に追加しない。

検索対象は要求、理由、仕様とする。ID は検索対象に含めない。

- 要求検索: 要求本文を対象に検索する
- 理由検索: 理由本文を対象に検索する
- 仕様検索: 仕様本文を対象に検索する
- フリーワード検索: 要求、理由、仕様を横断して検索する

検索結果では一致したノードを一覧表示し、選択するとキャンバス上の該当ノードを強調表示する。

## 12. 理由の表示

理由はデフォルトで折りたたんで表示する。
上位要求と下位要求の右端に V ボタンを配置し、押下時に理由を展開または折りたたむ。
子追加の楕円領域内では、重なっている理由展開・折りたたみ操作より子追加を優先する。同一クリックで理由表示を変えてから子追加する動作にはしない。楕円外の理由操作と、理由操作へフォーカスしたキーボード操作は通常どおり有効とする。詳細は§8を参照する。
展開中は理由の全文をノード内に表示する。
保存済み文書を開く場合は、ノードごとに保存された理由の展開・折りたたみ状態を復元する。
理由の展開によってノードサイズが変わる場合は、影響するサブツリーと接続線を必要な範囲で再配置する。

子ノードを非表示にするサブツリー折り畳みは、理由の表示切り替えとは別の将来対応機能とする。

## 13. エクスポート時の警告

YAML 保存では、理由が空でも警告を表示しない。
USDM 表、Excel などのファイルエクスポート時は、理由が空の要求を警告一覧に表示する。
警告は出力を妨げず、ユーザーは確認後にダウンロードを続行できる。

## 14. 接続線

接続線は SVG で描画する。

- 線種: ベジェ曲線
- 矢印: 親から子へ向かう方向を表示
- 子ノードへの接続位置: 親ノードの下辺中央から出る
- 親ノードからの接続位置: 子ノードの左辺中央に入る
- 選択中ノードに関係する線を強調表示

背景、上位要求、下位要求のいずれも、子ツリーへの線は下側から曲線で伸ばす。複数の子ノードがある場合も、同じ下辺中央を起点として各子ノードの左辺中央へつなぐ。子ノードを持たないノードには、子向けの接続線を表示しない。

子は親の下へ配置し、曲線は親の下辺から下方向へ出て、親の中心と右端の中間に揃えた子の左辺へ滑らかに入る見え方とする。理由の展開や本文の変化でノード高さが変わった場合も、子と後続サブツリーを必要な範囲で下へ移動し、接続線を新しい下辺・左辺へ追従させる。詳細は [LayoutDesign.md](LayoutDesign.md) の配置規則・接続線設計を参照する。

ベジェ曲線は親子関係の接続線にだけ使用し、関連する下位要求への参照には接続線を表示しない。

関連する下位要求を線で表示する機能を将来追加する場合は、親子接続線とは別の関連リンクとして表示する。

## 17. 大規模データ時の表示

多数のノードを含む文書でも、画面に表示されていないノードの文書データは失わない。論理レイアウトと画面上の描画対象を分離し、将来、ビューポートと一定の周辺余白を優先して描画できるようにする。周辺余白の具体値は性能試験と操作確認後に決定する。

ビューポート外非描画は v1.0 の必須機能とはせず、2,000ノードの性能試験が目標未達の場合に v1.0 の投入候補として再評価する。サブツリー折り畳みは将来対応とする。検索結果や選択対象へ移動する際の表示・ズーム動作も今後決定する。

v1.0 は2,000ノードを実用的な操作性の性能評価対象とする。2,000ノードを超える文書も開けるが、v1.0 の性能保証対象外とする。10,000ノード以上は YAML の保存・読み込み目標であり、全件を同時描画して快適に操作できることを意味しない。

2,000ノードでは、初回表示2秒以内、ノード追加200ms以内、ノード編集200ms以内、局所レイアウト500ms以内、YAML 保存1秒以内を設計上の初期目標とする。パン、ズーム、背景のツリー全体ドラッグは60fpsを目標とし、平均45fps以上かつ30fps未満の状態が継続しないことを目指す。瞬間的な低下だけでは不合格とせず、正式な保証値は性能試験後に確定する。

一次性能評価は macOS / Apple Silicon M2 / Google Chrome 最新安定版で行う。Safari 最新版は互換性と実動作を確認する。メモリは読み込み、操作、クローズを反復しても使用量が増加し続けないことを確認し、絶対上限値は実測後に決定する。

## 18. 手動配置

### 背景のドラッグによるツリー全体移動

背景本体を主ボタンでドラッグすると、背景、配下の全ノード、接続線が一体で移動する。内部の親子配置や兄弟順は保つ。背景の下辺にある子追加楕円と、編集・削除などの操作部品からは移動を開始しない。ドラッグ後に本文クリックや子追加を発火させない。

| 操作箇所・状態 | 結果 |
|---|---|
| キャンバス空白のドラッグ | パン |
| キャンバス空白のダブルクリック | 背景追加ダイアログ |
| 背景本体のドラッグ | その背景のツリー全体移動 |
| 子追加楕円のクリック | 子追加。理由操作・背景移動より優先 |
| 上位要求・下位要求・仕様本体のドラッグ | 個別ノード移動・パン・ツリー移動は行わない |
| 他ツリーと重ならない位置で離す | 移動を確定し、背景配置位置を保存対象へ反映 |
| 他ツリーと重なる位置で離す | ツリー全体をドラッグ開始位置へ戻し、移動できなかったことを通知。他ツリーは動かさない |
| Escape・ポインターキャンセル・画面非アクティブ化 | 移動を取り消し、開始位置へ戻す |

重なる移動候補は移動不可と分かる表示とする。ドラッグ中にパンやズームを併発させず、無効・取り消しの移動を未保存変更として残さない。確定した背景配置位置は、ズーム・パンとは独立してYAMLへ保存し、再読込で復元する。

### ツリーが大きくなる場合

子追加、本文編集、理由展開などで他ツリーと重なる場合は、操作元の背景位置を保ち、他ツリーを自動移動して重複を解消する。移動した背景位置も保存する。縮小や削除では空白を自動で詰め直さない。重複判定と自動移動の詳細は [LayoutDesign.md](LayoutDesign.md) §7を参照する。

2026-10-28の変更方針では、右側にあるツリーへ広がって重なる場合は相手ツリーを右へ、下側にあるツリーへ広がって重なる場合は相手ツリーを下へ押し出す。右へ移動する際は上下位置を、下へ移動する際は左右位置を保つ。移動先でさらに重なる場合は、その衝突方向に応じて連鎖的に解消する。斜めの位置など方向が一意に決まらない場合の補完ルールは [LayoutDesign.md](LayoutDesign.md) §7.3.1の暫定設計とする。背景ドラッグで重なったときは、従来どおり他ツリーを押し出さず開始位置へ戻す。

上位要求・下位要求・仕様の個別手動配置、手動並べ替え、「自動配置へ戻す」操作は将来対応とする。

2026-10-27に、空白ダブルクリックによる背景追加、背景本体からのツリー全体移動、無効移動・取消の復元、子追加・理由展開・実測サイズ変更に伴う重複制御を実装した。`Home` は `DocumentEditingSession` を介して文書・ビュー・背景位置を一括確定し、初期補完・重複補正や移動拒否を表示する。2026-10-28にはCoreの押し出しを、変更前の外接矩形から右・下を選ぶ方式へ変更した。方向不明時の補完は暫定ルールに従い、縮小で詰め直さない動作とドラッグの拒否・復元は維持する。今回の表示・操作の確認範囲と未確認条件は [QA_Q_sheet.md](QA_Q_sheet.md) を参照し、旧方式の画面結果とは区別する。

背景位置を含む形式3のYAML保存・読込はCoreまで実装した。「保存」「開く」のUIは今回接続せず、本文編集・削除UIやUndo / Redoも追加していない。通常操作は背景単位で再計算し、より細かいサブツリー再計算・Revision付き実測キャッシュは残課題である。新規自動テストと、今回のSafari実UIの確認範囲・未確認条件は [QA_Q_sheet.md](QA_Q_sheet.md) を参照する。従来の子追加・楕円強調の試験結果を今回の背景移動の合格結果として扱わない。
